# The P Alpha 验收

本清单区分云端自动检查、模拟器检查与小米 15 Pro 真机检查。待执行项不代表通过。

## 自动检查

- `spotlessCheck`：新工程 Kotlin 与 Gradle Kotlin DSL 格式。
- `assembleDebug`：生成原生 APK，独立 applicationId `com.thep.android.dev`。
- `:core:model:test`：重量精度、数值边界、正式组训练量、估算 1RM、周界/时区、跨午夜与补录训练日期、计时。
- `:core:data:testDebugUnitTest`：旧格式解析、确定性 ID、空值、异常 JSON/大小/日期、独立课表、有氧原值、V5 备份格式标记和补录日期保留。
- `lintDebug`：API 兼容性与 Android 静态检查。
- `:core:database:connectedDebugAndroidTest`：外键失败完整回滚、关闭重开数据库后记录保留。
- `:app:connectedDebugAndroidTest`：训练快照、重复结束、上次重量、备份往返、幂等导入、无效输入、唯一当前计划、原生 Compose 训练流程。

## 小米 15 Pro 安装与验收（需要用户实际执行）

1. 在旧 FitWave 导出完整 JSON，另存备份；保留旧应用，不卸载、不清除数据。
2. 安装新的 The P Debug APK；确认与旧应用同时存在，图标是已确认 Logo，名称为 The P。
3. 断网启动，确认四分化课表；创建一个新计划，编辑训练日、排序与动作目标，切回原计划。
4. 开始训练，录入 20.25 kg、10 次、RIR 2，点击“完成并保存”。确认出现“撤销完成”。添加并完成一个热身组。
5. 将 App 切到后台并强杀进程，再打开，继续未结束训练。已确认的组应仍然存在；未确认的输入不作为已保存数据。
6. 核对休息时间；暂停、继续，返回前台后计时不依赖界面刷新次数。Alpha 不承诺后台到时通知。
7. 更改未来计划后回看当前训练，动作快照保持不变。结束训练，核对历史、正式组训练量、PR 和标注为估算的 1RM。重复点击结束不增加次数。
8. 在历史中修改已完成组并保存，核对统计更新；返回首页仍可新建训练。
9. 添加体重/腰围、快走/爬楼，核对进度页。
10. 先导出 V5 JSON，再选择旧版 JSON 查看预览。核对源场次数、完成组数、训练量、身体/有氧条数及警告，明确确认后导入。
11. 再选同一文件，显示已导入，场次不重复。检查最早、最近及含自定义动作的记录；使用损坏 JSON 应拒绝且不产生部分记录。
12. 在新的专用测试安装中恢复 V5 备份，对账课表、场次、组数、身体/有氧与训练量。不要卸载或清除原有应用来模拟新安装。

小米/HyperOS 的实际系统版本、安装结果、杀进程恢复、键盘布局与长时间使用需记录；此云环境不能替代真机结论。
